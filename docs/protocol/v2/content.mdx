A content block is one piece of user-facing content: text, an image, audio, a link to a resource, or an embedded resource.

Content blocks appear in:

- User prompts sent via [`session/prompt`](/protocol/v2/prompt-lifecycle#1-user-message)
- Language model output reported through [`session/update`](/protocol/v2/prompt-lifecycle#3-agent-reports-output) notifications as message updates or streamed chunks
- Progress updates and results from [tool calls](/protocol/v2/tool-calls), including streamed tool-call content chunks

## Plain text and Markdown

Display strings are plain text unless the field specifies Markdown. Clients **SHOULD NOT** render plain-text fields as Markdown. These include tool call and session titles, command and config option names, labels, input hints, and error messages. For example, the underscores in a tool call title of `Read /work/_draft_.md` are part of the filename, not emphasis.

When displaying the following fields, Clients **SHOULD** render them as [CommonMark](https://spec.commonmark.org/) and **MAY** support [GitHub Flavored Markdown](https://github.github.com/gfm/) extensions such as tables:

- `text` in a [text content block](#text-content), wherever the block appears.
- `content` in a [plan entry](/protocol/v2/agent-plan#plan-entries) or a [Markdown plan](/protocol/v2/agent-plan#markdown-plans).
- `description` on an [authentication method](/protocol/v2/authentication#authentication-method-types), a [command](/protocol/v2/slash-commands), a [config option or one of its select values](/protocol/v2/session-config-options), a [permission request](/protocol/v2/tool-calls#requesting-permission), or a [subagent](/protocol/v2/subagents).

The `description` of a [notice](/protocol/v2/prompt-lifecycle#session-notices), a [resource link](#resource-link), or an [elicitation form, property, or option](/protocol/v2/elicitation#form-mode) is plain text. See [Rendering Agent content](/protocol/v2/security#rendering-agent-content) for handling raw HTML and links when displaying Markdown.

Payloads have their own formats. An embedded resource's `text` is the resource itself, a diff's `patch.text` is in the format named by `patch.format`, and terminal output carries bytes. None of these is a text content block.

## Content types

Content from the Agent is untrusted. See [Rendering Agent Content](/protocol/v2/security#rendering-agent-content) and [URIs and Remote Resources](/protocol/v2/security#uris-and-remote-resources).

ACP's `ContentBlock` is compatible with, and a superset of, the [Model Context Protocol (MCP) 2026-07-28 `ContentBlock`](https://modelcontextprotocol.io/specification/2026-07-28/schema#contentblock), so Agents can forward content from MCP tool outputs unchanged. ACP adds an optional `uri` on image content, `_meta` on icons and annotations, extensible `Role` and `IconTheme` values, and the open `type` fallback described below.

A content type from a later MCP revision that ACP doesn't define isn't forwarded as is. Agents convert it to a supported type, such as an embedded resource, or omit it.

Content block `type` values can be custom or future variants when the receiver can preserve or display them generically. Custom content block types **MUST** begin with `_`. Unknown non-underscore content block types are reserved for future ACP variants. In prompts, Clients send only baseline content types (`text` and `resource_link`) and content types the Agent advertised, including custom types advertised through a [custom capability](/protocol/v2/extensibility#advertising-custom-capabilities), and Agents **MUST** reject others with `-32602`.

When displaying Agent output, Clients **SHOULD** show text content. For image, audio, resource, and resource link content they can't render, Clients **SHOULD** show a placeholder with whatever identifies it, such as its name, title, URI, or MIME type, and **SHOULD NOT** drop it silently. Agents that need content to reach the user in a particular form **SHOULD** also include it as text.

`annotations` are hints with [MCP semantics](https://modelcontextprotocol.io/specification/2026-07-28/schema#annotations). In `audience`, `user` means the person using the Client and `assistant` means the Agent's model. `priority` ranges from 0 (least important) to 1 (most important). `lastModified` is the time the underlying resource was last modified, as an ISO 8601 string such as `2025-01-12T15:00:58Z`. Clients **MAY** collapse or hide content whose `audience` doesn't include `user`, which is an exception to the display rule above.

### Text content

Adjacent text blocks form one continuous text. Clients **SHOULD** join them without a separator before rendering. This applies wherever text blocks appear, including in user and Agent messages, thoughts, tool-call content, and compaction summaries.

```json
{
  "type": "text",
  "text": "What's the weather like today?"
}
```

All Agents **MUST** support text content blocks when included in prompts.

<ParamField path="text" type="string" required>
  The text to display. It can be plain text or
  [Markdown](#plain-text-and-markdown).
</ParamField>

<ParamField path="annotations" type="Annotations">
  Optional metadata about how the content should be used or displayed. [Learn

</ParamField>

### Image content <Icon icon="asterisk" size="14" />

Images can be included for visual context or analysis.

```json
{
  "type": "image",
  "mimeType": "image/png",
  "data": "iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mNkYPhfDwAChwGA60e6kgAAAABJRU5ErkJggg=="
}
```

<Icon icon="asterisk" size="14" /> Requires the `image` [prompt

<ParamField path="mimeType" type="string" required>

</ParamField>

<ParamField path="annotations" type="Annotations">

### Embedded resource <Icon icon="asterisk" size="14" />

Complete resource contents embedded directly in the message.

```json
{
  "type": "resource",
  "resource": {
    "uri": "file:///home/user/script.py",
    "mimeType": "text/x-python",
    "text": "def hello():\n    print('Hello, world!')"
  }
}
```

This is the preferred way to include context in prompts, such as when using @-mentions to reference files or other resources.

By embedding the content directly in the request, Clients can include context from sources that the Agent might not have direct access to.

<Icon icon="asterisk" size="14" /> Requires the `embeddedContext` [prompt
capability](/protocol/v2/initialization#session-prompt-capabilities) when
included in prompts.

<ParamField path="resource" type="EmbeddedResourceResource" required>
  The embedded resource contents, which can be either:

  <Expandable title="Text resource">
    <ParamField path="uri" type="string" required>
      The URI identifying the resource
    </ParamField>

    <ParamField path="text" type="string" required>
      The contents of the resource. Its `mimeType`, when provided, describes the
      format, for example `text/plain` or `text/markdown`.
    </ParamField>

    <ParamField path="mimeType" type="string">
      Optional MIME type of the text content
    </ParamField>

  </Expandable>

  <Expandable title="Blob resource">
    <ParamField path="uri" type="string" required>
      The URI identifying the resource
    </ParamField>

    <ParamField path="blob" type="string" required>
      Base64-encoded binary data
    </ParamField>

    <ParamField path="mimeType" type="string">
      Optional MIME type of the blob
    </ParamField>

  </Expandable>
</ParamField>

<ParamField path="annotations" type="Annotations">
  Optional metadata about how the content should be used or displayed. [Learn
  more](https://modelcontextprotocol.io/specification/2026-07-28/schema#annotations).
</ParamField>

### Resource link

References to resources that the receiver may be able to read.

All Agents **MUST** support resource links when included in prompts.

```json
{
  "type": "resource_link",
  "uri": "file:///home/user/document.pdf",
  "name": "document.pdf",
  "mimeType": "application/pdf",
  "icons": [
    {
      "src": "https://example.com/icons/pdf.png",
      "mimeType": "image/png",
      "sizes": ["48x48"]
    }
  ],
  "size": 1024000
}
```

<ParamField path="uri" type="string" required>
  The URI of the resource
</ParamField>

<ParamField path="name" type="string" required>
  A human-readable name for the linked resource, in plain text
</ParamField>

<ParamField path="mimeType" type="string">
  The MIME type of the resource
</ParamField>

<ParamField path="title" type="string">
  Optional plain-text title for displaying the resource to users
</ParamField>

<ParamField path="description" type="string">
  Optional human-readable description shown with the link. It describes the
  resource contents in plain text.
</ParamField>

<ParamField path="icons" type="Icon[]">
  Optional icons Clients can display for this resource. Each icon requires a
  `src` URI and may include `mimeType`, `sizes`, and `theme`. `theme` names the
  background the icon is designed for: `light` or `dark`.
</ParamField>

<ParamField path="size" type="integer">
  Optional size of the resource in bytes
</ParamField>

<ParamField path="annotations" type="Annotations">
  Optional metadata about how the content should be used or displayed. [Learn
  more](https://modelcontextprotocol.io/specification/2026-07-28/schema#annotations).
</ParamField>
