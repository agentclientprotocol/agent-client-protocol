This page describes ACP's trust model and security guidance that spans features. Guidance for a single feature is on that feature's page; see [Feature Guidance](#feature-guidance).

## Trust Model

- The Agent runs with whatever permissions its process is given. ACP itself does not sandbox it.
- Files, web pages, tool results, and MCP servers can influence Agent output. Treat every Agent-authored string, URI, and path as untrusted, including replayed content.
- Permission requests are advisory: the Agent performs operations and is responsible for honoring the user's decision. A Client cannot prevent an operation the Agent performs without asking.
- `info` in `initialize` is self-reported. Implementations **SHOULD NOT** use it for security decisions, and Clients **SHOULD** identify the Agent from their own launch configuration.

Out of scope: a malicious Agent binary, detecting prompt injection, and operating-system sandboxing.

## Rendering Agent Content

This applies to all Agent-authored display text, including messages, thoughts, tool calls, plans, commands, config options, notices, session titles, authentication methods, permission requests, and elicitations.

- Clients **SHOULD NOT** run scripts from Agent content, and **SHOULD** disable or sanitize raw HTML when rendering Markdown.
- Clients **SHOULD NOT** automatically run active content, such as diagram renderers, that can fetch resources or execute code.
- Clients **SHOULD NOT** open links from Agent content without user action, and **SHOULD** show the full target and get user confirmation before handing a link with a scheme other than `http` or `https` to the operating system or another handler.
- Clients **SHOULD** show the full link target when it differs from the link text.
- Clients **SHOULD** reveal or remove bidirectional, zero-width, and tag characters in commands, paths, URLs, diffs, and permission requests.
- Clients that print Agent text to a terminal **SHOULD** neutralize terminal control sequences in it.
- Clients **SHOULD** keep Agent [slash commands](/protocol/v2/draft/slash-commands) distinguishable from their own commands.
- Clients **MAY** bound or throttle permission requests, elicitations, and output.

## URIs and Remote Resources

This applies to `uri` on images, resource links, and embedded resources, to icon `src`, and to URLs in Markdown.

- Clients **SHOULD** render images from `data` and **SHOULD NOT** fetch Agent-supplied remote URIs without user action. A request can leak data through its URL.
- Automatic fetches **SHOULD** use only `https:` or `data:` URIs, **SHOULD NOT** carry credentials, **SHOULD** refuse loopback and private-network targets, and **SHOULD** bound the response size.
- Clients **SHOULD NOT** run scripts in SVG images from Agent content.
- Clients **SHOULD NOT** read a `file:` URI from Agent content outside the session's workspace roots without user action.
- Agents **SHOULD** apply the workspace roots and these fetch rules to URIs in prompts.

## Workspace Roots

The workspace roots are `[cwd, ...additionalDirectories]`. They declare the session's scope, and confine shell commands only when a sandbox enforces them.

- Clients **SHOULD** only include directories the user expects the Agent to access, such as the workspace or directories the Client provides, like skills.
- Agents **SHOULD NOT** treat model output, Agent content, or replayed history as granting access outside the workspace roots. Access outside them goes through a permission request.
- Implementations that enforce the workspace roots **SHOULD** check the resolved path at the time of use, compare paths by component, and fail closed.
- Tool-call `locations` and diff paths do not grant access. Clients **SHOULD NOT** automatically open locations outside the workspace roots.
- Agents **SHOULD** request permission before writing files that control execution or approval, such as version-control hooks, editor or Agent settings, and MCP configuration.

## Credentials

- Implementations **SHOULD NOT** put credentials in `_meta`, including `traceparent`, `tracestate`, and `baggage`. [Preserving unknown values](/protocol/v2/draft/extensibility#enum-and-tagged-union-variants) does not require storing or replaying credentials.
- Session, message, tool-call, and terminal IDs are not credentials.

## Prompt Injection

- Agents **SHOULD** treat embedded resources, files, tool results, and MCP results as data, not as user instructions.
- Agents **SHOULD** request permission before sending data off the machine after reading untrusted content.
- Clients **SHOULD NOT** open links, run commands, change settings, or send data based only on Agent-authored text.

## Intermediaries

- Any process attached to the Agent's stdio, including a proxy, acts with the Client's authority.
- Intermediaries **SHOULD NOT** answer permission requests or elicitations for the user except under user-configured policy, and **SHOULD** forward `subject` unchanged.
- An Agent serving more than one user **SHOULD** scope `session/list`, `session/resume`, permission requests, and elicitations to the user that owns the session.

## Transports

[Custom transports](/protocol/v2/draft/transports#custom-transports) **SHOULD** document their security considerations, including how peers authenticate.

## Residual Risk

A user can approve a harmful operation, prompt injection can steer operations the user allowed, and an Agent can act without asking.

## Unstable Features

- A [system prompt](/protocol/v2/draft/session-setup#system-prompt-unstable) carries more weight than user turns. Clients **SHOULD** only send content they trust at that level, and Agents **MAY** reject it.
- Clients **SHOULD NOT** read a plan file `uri` outside the session's workspace roots without user action.
- [Session-directed messages](/protocol/v2/draft/prompt-lifecycle#session-directed-messages-unstable) are Agent content. Clients **SHOULD** attribute them to the sending session and **SHOULD NOT** present them as user messages.
- Provider `headers` are credentials. Agents **SHOULD NOT** return them from `providers/list`.
