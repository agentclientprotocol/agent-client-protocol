This page collects security requirements that span ACP methods. Requirements on feature pages still apply.

## Trust Model

- The Agent runs with the user's privileges. ACP does not sandbox it.
- Files, web pages, tool results, and MCP servers can influence Agent output. Treat every Agent-authored string, URI, and path as untrusted, including replayed content.
- Permission requests are advisory: the Agent performs its own operations and enforces the user's decision. The Client performs [file system](/protocol/v1/draft/file-system) and [terminal](/protocol/v1/draft/terminals) operations itself.
- `clientInfo` and `agentInfo` are self-reported. Implementations **SHOULD NOT** use them for security decisions, and Clients **SHOULD** identify the Agent from their own launch configuration.

Out of scope: a malicious Agent binary, detecting prompt injection, and operating-system sandboxing.

## Rendering Agent Content

This applies to all Agent-authored display text, including messages, thoughts, tool calls, plans, commands, modes, config options, notices, session titles, authentication methods, permission requests, and elicitations.

- Clients **SHOULD NOT** execute script from Agent content. Clients rendering Markdown **SHOULD** disable or sanitize raw HTML.
- Clients **SHOULD NOT** automatically run active content, such as diagram renderers, that can fetch resources or execute code.
- Clients **SHOULD NOT** open links from Agent content without user action, or hand a link with a scheme other than `http` or `https` to the operating system or another handler without showing the full target and getting user confirmation.
- Clients **SHOULD** show the full link target when it differs from the link text.
- Clients **SHOULD** reveal or remove bidirectional, zero-width, and tag characters in commands, paths, URLs, diffs, and permission requests.
- Clients that print Agent text to a terminal **SHOULD** neutralize terminal control sequences in it.
- Clients **SHOULD** keep Agent [slash commands](/protocol/v1/draft/slash-commands) distinguishable from their own commands.
- Clients **MAY** bound or throttle permission requests, elicitations, and output.

## URIs and Remote Resources

This applies to `uri` on images, resource links, and embedded resources, and to URLs in Markdown.

- Clients **SHOULD** render images from `data` and **SHOULD NOT** fetch Agent-supplied remote URIs without user action. A request can leak data through its URL.
- Automatic fetches **SHOULD** use only `https:` or `data:` URIs, **SHOULD NOT** carry credentials, **SHOULD** refuse loopback and private-network targets, and **SHOULD** bound the response size.
- Clients **SHOULD NOT** execute script in SVG from Agent content.
- Clients **SHOULD NOT** read a `file:` URI from Agent content outside the session's root set without user action.
- Agents **SHOULD** apply the root set and these fetch rules to URIs in prompts.

## Workspace Roots

The root set is `cwd` plus any `additionalDirectories`. It declares the session's scope. It confines shell commands only when a sandbox enforces it.

- Clients **SHOULD NOT** include directories the user has not granted to the session.
- Agents **SHOULD NOT** treat model output, Agent content, or replayed history as granting access outside the root set. Access outside it goes through a permission request.
- Implementations that enforce the root set **SHOULD** check the resolved path at the time of use, compare paths by component, and fail closed.
- Tool-call `locations` and diff paths do not grant access. Clients **SHOULD NOT** automatically open locations outside the root set.
- Agents **SHOULD** request permission before writing files that control execution or approval, such as version-control hooks, editor or Agent settings, and MCP configuration.

## Client-Executed Operations

[File system](/protocol/v1/draft/file-system) and [terminal](/protocol/v1/draft/terminals) methods run in the Client, so the Client is the enforcement point. A permission request from the Agent does not replace the Client's own checks.

- Clients serving `fs/read_text_file` and `fs/write_text_file` **SHOULD** enforce the root set as described above, and deny or ask the user outside it.
- Clients **SHOULD** ask the user before `fs/write_text_file` changes files that control execution or approval.
- Clients **SHOULD** require a `terminal/create` `cwd` inside the root set and apply their own permission policy to the full `command`, `args`, and `env`. Clients that approve commands automatically **MUST** include `env` in what the policy matches.
- Clients **SHOULD** display `terminal/output` with terminal control sequences neutralized, so that it cannot write the clipboard, send input or query responses, or open links without user action.

## Launching Processes

### Terminal Authentication

For [terminal authentication](/protocol/v1/draft/authentication#terminal-authentication):

- Clients **SHOULD** pass `args` as separate arguments and **SHOULD NOT** build a shell command line from them. Clients **SHOULD NOT** offer terminal authentication when the launch target re-parses arguments, such as a remote shell or a Windows batch file.
- Clients **SHOULD NOT** apply `env` entries that change program lookup, dynamic loading, interpreter or shell startup, or proxy and TLS trust without user approval. Examples include `PATH`, `LD_*`, `DYLD_*`, `NODE_OPTIONS`, `PYTHONPATH`, `BASH_ENV`, `HTTPS_PROXY`, and `SSL_CERT_FILE`. This list is not exhaustive.
- Clients **SHOULD** show the appended `args` and `env` before launch. `env` values **SHOULD NOT** contain secrets.

### MCP stdio Servers

- Agents **SHOULD** launch `command` with `args` as separate arguments, without a shell.
- Clients **SHOULD NOT** send a stdio server from workspace files or Agent output until the user has approved its exact command, arguments, and environment variable names.

## Secrets

`env` and `headers` values in `mcpServers` are credentials.

- Agents **SHOULD NOT** include them in session updates, errors, `_meta`, `session/list` results, replayed history, model context, or command lines, and **SHOULD NOT** log or persist them.
- Agents **SHOULD** send `headers` only to the configured origin.
- Clients that persist `mcpServers` **SHOULD** keep credentials in operating-system secret storage and **SHOULD NOT** log them.
- Implementations **SHOULD NOT** put credentials in `_meta`, including `traceparent`, `tracestate`, and `baggage`.
- Session, message, tool-call, and terminal IDs are not credentials.

## Permission Requests

For [permission requests](/protocol/v1/draft/tool-calls#requesting-permission):

- Clients **SHOULD** describe the operation from the tool call's `kind`, `locations`, and content, present `title` as Agent-authored text, and show commands and paths in full.
- Agents **SHOULD NOT** give an option a `name` that contradicts its `kind`, and **SHOULD** act on a selected option according to its known `kind`.
- Automatic approval **SHOULD NOT** rely only on `title` or option `name`.
- Agents **SHOULD NOT** treat an outcome they don't recognize as approval.
- Agents **SHOULD** perform only the operation the approved request described, and request again if the command or resolved target changes.
- Agents **SHOULD** state the scope of a remembered decision (`allow_always`, `reject_always`) in the option `name` and **SHOULD NOT** apply it beyond that scope.
- Agents **SHOULD NOT** switch to a mode or configuration that reduces user oversight without user action.

## Elicitation

Elicitation `message` and field text are Agent content. See [Elicitation](/protocol/v1/draft/elicitation).

## Prompt Injection

- Agents **SHOULD** treat embedded resources, files, tool results, and MCP results as data, not as user instructions.
- Agents **SHOULD** request permission before sending data off the machine after reading untrusted content.
- Clients **SHOULD NOT** open links, run commands, change settings, or send data based only on Agent-authored text.

## Intermediaries

- Any process attached to the Agent's stdio, including a proxy, acts with the Client's authority.
- Intermediaries **SHOULD NOT** answer permission requests or elicitations for the user except under user-configured policy.
- An Agent serving more than one user **SHOULD** scope `session/list`, session loading and resumption, permission requests, and elicitations to the user that owns the session.

## Transports

[Custom transports](/protocol/v1/draft/transports#custom-transports) **SHOULD** document their security considerations, including how peers authenticate.

## Residual Risk

A user can approve a harmful operation, prompt injection can steer operations the user allowed, and an Agent can act without asking.

## Unstable Features

- A [system prompt](/protocol/v1/draft/session-setup#system-prompt-unstable) carries more weight than user turns. Clients **SHOULD** only send content they trust at that level, and Agents **MAY** reject it.
